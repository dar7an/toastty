# Toastty verification — 2026-09-16

Local development work on `codex/toastty`, based on Ghostty commit
`f9a3f24a56bf05f70894e1a084809d4fffadf420`, including the previously uncommitted
workspace, split, and dependency work. The original Ghostty checkout was preserved.
This report describes local checks, not a hosted CI or public release result.

- macOS application and test build succeeded with Xcode 27.0, macOS 27.0, Apple Silicon.

- Zig configuration tests: **195 passed**, using
  `zig build test -Dtest-filter=config.Config --summary all`.

- `git diff --check`, plist validation, and script syntax checks passed.
- The app uses `com.dar7an.toastty.debug`, executable `toastty`, display name Toastty,

## Native desktop checks

The development app was launched from `macos/build/Debug/Toastty.app`, with a
temporary configuration and preference suite. The user's Ghostty settings were
not changed.

- The workspace sidebar appears by default, with padded rows and a four-point
  title/path gap. The long repository path remains readable at the normal width.
- Light and dark appearances were inspected in the running app.
- Adding a second tab, collapsing/expanding the sidebar, and creating a right split
  worked. The native toolbar and traffic lights remained aligned.
- Creating a project from `/tmp` produced title `tmp` and subtitle `/tmp`, without
  a naming dialog. Returning to `toastty` restored its two tabs and the split
  terminal state, including the shell's changed directory.
- About Toastty displays the buttered-toast icon, Ghostty/libghostty credit, a
  link crediting Mitchell Hashimoto and contributors, and the complete copyright.
  A clipped copyright line found during testing was corrected by sizing the window
  to its content and allowing the notice to wrap.

## Tab and context-menu polish follow-up

- **30 focused tests passed** across `TerminalPaneLayoutMenuTests`,
  `ProjectTabStripTests`, `ProjectWindowLayoutTests`, and `TabSidebarModelTests`.
  The test build and strict lint for the four changed Swift files passed.
- The New Project test sends Command-P through the actual File menu and checks
  that the new project keeps the current terminal directory. Command-P also
  created a second project in the live app; Command-T added tabs only within it.
- Split controls use 48 × 40-point native button targets with 8-point gaps and
  inset symbols. Tests invoke all six split/arrange actions against the clicked
  pane target and check the rendered button dimensions. Split Right was also
  exercised from a live tab context menu.
- In the running app, the selected tab's close button hid away from the strip,
  appeared on hover, and closed only that tab. Titles retained their centered
  position. Two- and three-tab layouts were inspected in dark appearance; the
  two-tab strip and hover control were also inspected in light appearance.
- Native Liquid Glass is confined to the selected tab and add button above a
  subdued rail. Reduced transparency/high contrast use a solid bordered fallback;
  reduced motion disables the close-button fade. Full assistive-technology
  traversal remains part of the release matrix below.
